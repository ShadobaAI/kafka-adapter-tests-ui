# 1С: Адаптер Kafka — UI-Тесты

![Платформа](https://img.shields.io/badge/1С-8.3.21+-blue)

Набор UI-тестов для проверки поведения [1С: Адаптер Kafka](https://github.com/ShadobaAI/kafka-adapter).

## Назначение

Репозиторий содержит тесты для проверки изменений адаптера:

- **UI-тесты Vanessa Automation** — сценарии в каталоге `features`, которые проверяют поведение адаптера через интерфейс пользователя;

> Репозиторий предназначен только для разработки и проверки изменений адаптера. В промышленную эксплуатацию не поставляется.

## Инструменты

- [Vanessa Automation](https://pr-mex.github.io/vanessa-automation/) — UI-тесты для проверки пользовательских сценариев.

## Работа через ИИ

Используется навык `vanessa-ui-tests`, общий [Vanessa MCP toolkit](../../tools/ai/ui/README.md)
и коллекция `vanessa` установленного MCP `v8std`. Во время работы исходные
репозитории и сайт документации Vanessa не требуются.

Локальный профиль хранится в `.vanessa/profile.json` и не попадает в Git.
Он связывает общие команды с основной базой контура `kfk-edt`, платформой,
runtime и этим каталогом features. Параметры подключения задаются без пароля.

Из корня этого репозитория:

```powershell
node ../../tools/ai/ui/vanessa.mjs configure --profile .vanessa/profile.json
node ../../tools/ai/ui/vanessa.mjs start --profile .vanessa/profile.json
node ../../tools/ai/ui/vanessa.mjs setup --profile .vanessa/profile.json
node ../../tools/ai/ui/vanessa.mjs doctor --profile .vanessa/profile.json
node ../../tools/ai/ui/vanessa.mjs list --profile .vanessa/profile.json
node ../../tools/ai/ui/vanessa.mjs run --profile .vanessa/profile.json --feature features/011_Справочники_ФормаСписка.feature --scenario 'Открытие формы списка справочника "Консьюмеры (Kafka)" (кфкКонсьюмеры)'
```

Если профиль ссылается на `userEnv`, перед командами задайте эту переменную среды
локально. Имя пользователя не включается в tracked профиль или примеры.
Менеджер и TestClient всегда запускаются в режиме «Такси» (`/iTaxi`).

ИИ исследует целевую форму, актуализирует feature-файл, проверяет его синтаксис
и запускает затронутый сценарий. Для приёмки нужен успешный прогон с начала
и подтверждение ожидаемых проверок. Исправление теста сохраняет его назначение.
`run` удерживает одну блокировку клиента до получения результата выбранного
сценария. В Single 1.2.043.45 / MCP 1.31 перед следующим запуском иногда требуется
штатный переход из редактора в дерево шагов для получения полного состояния MCP;
навык описывает проверку и восстановление этого состояния.

`VAParams.json` остаётся CI-профилем. Для MCP используется отдельный интерактивный
JSON: без автоматического запуска всех сценариев и завершения 1С. Первичная
проверка настройки ограничена открытием форм. Сценарии `013_Справочники_Запись.feature`
изменяют существующие элементы основной базы; перед их запуском определяется
стратегия fixtures и сохранения состояния.
