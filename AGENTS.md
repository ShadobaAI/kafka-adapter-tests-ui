# Инструкции для агента: UI-тесты Kafka Adapter

Применяйте обязательные [инструкции рабочего пространства](../../AGENTS.md). При конфликте локальные правила ниже имеют приоритет над общими.

Репозиторий содержит сценарии Vanessa Automation для Kafka Adapter. Актуальные сценарии и результаты их выполнения — основные свидетельства поведения тестов.

## Работа со сценариями

- Редактируйте feature-файлы и другую конфигурацию тестов, не относящуюся к исходникам 1С, напрямую в UTF-8, без EDT. Сохраняйте язык Gherkin, имена, отступы, fixtures и стиль сценариев.
- Для исследования UI, записи, изменения, запуска и отладки сценариев используйте `$vanessa-ui-tests` с локальным профилем `.vanessa/profile.json`.
- Запускайте только затронутые features или сценарии командами, документированными в этом репозитории, когда среда доступна.
- Первичную проверку настройки выполняйте сценарием `Начальное состояние новой карточки брокера` из `features/Справочники/Брокеры/ОсновныеОперации.feature`: он не записывает данные.
- Не изменяйте исходники продукта без явно заданной задачи на несколько репозиториев.

## Элементы и группы продюсеров и консьюмеров

- Для всех существующих и будущих UI-тестов `кфкПродюсеры` и `кфкКонсьюмеры` учитывайте оба вида объектов: элемент справочника и группу справочника. Группа — это диспетчер задач.
- Проверяйте применимые операции, сохранение состояния и права для элементов и диспетчеров задач отдельно. Ожидания для группы определяйте по её форме и доступным командам; поля и команды элемента не переносите на группу автоматически.
- Для проверок с записью создавайте собственные диспетчеры задач и восстанавливайте их состояние при сбое. Подготовленные группы `Диспетчер задач` не изменяйте как локальную очистку.

## Пользователи и сеансы

Менеджер тестов — основной управляющий клиент 1С с Vanessa Automation. Менеджер и каждый TestClient всегда запускаются в интерфейсе Такси (`/iTaxi`).

| Пользователь | Права | Назначение |
|---|---|---|
| `АдминистраторТакси` | Полный администратор ИБ | Всегда используется для менеджера тестов |
| `Администратор` | Полный администратор ИБ | Интерфейс 8.5; в тестах не используется |
| `АдминистраторKafka` | Администратор подсистемы Kafka; `кфкПолныеПрава` вместо `кфкБазовыеПрава` | TestClient для административных проверок |
| `ПользовательKafka` | Чтение/аудит подсистемы Kafka; `кфкБазовыеПрава` | TestClient для проверок ограниченных прав |

Набор тестов должен проверять права обоих пользователей Kafka: административные действия для `АдминистраторKafka` и ограничения режима чтения/аудита для `ПользовательKafka`. Выполняйте проверки в сеансе TestClient соответствующего пользователя; полные права менеджера не должны подменять проверяемые права.

Оба пользователя Kafka также получают роль `кфк_т_ДобавлениеИзменениеТестовыхДанных` для демонстрационных объектов расширения `examples` и общие роли запуска клиентов и БСП. Возможность изменять демонстрационные данные не даёт административных прав на подсистему Kafka.

## Инициализация новой базы

При создании любой новой тестовой ИБ обязательно выполняйте обе процедуры общего модуля `кфк_т_ТестовыеДанные` расширения `examples` в указанном порядке:

```bsl
кфк_т_ТестовыеДанные.ИнициализацияДанных();
кфк_т_ТестовыеДанные.ИнициализацияПользователей();
```

### `ИнициализацияДанных()`

Включает `кфкИспользоватьИнтеграцию` и `кфкИспользоватьПотоковыйРежим`, создаёт или обновляет следующие настройки обмена:

- Брокер `Брокер по умолчанию`: `localhost:29091` и `localhost:29092` включены, `localhost:29093` выключен; параметры подключения очищаются.
- В справочниках продюсеров и консьюмеров — по группе `Диспетчер задач`: два подпотока обработки и один подпоток транспорта. Все элементы ниже входят в соответствующую группу и используют брокера по умолчанию.

| Элементы | Объект метаданных | Топик |
|---|---|---|
| `Продюсер: ТестовыйСправочник`, `Консьюмер: ТестовыйСправочник` | `Справочник.кфк_т_ТестовыйСправочник` | `1c.test-catalogs` |
| `Продюсер: ТестовыйДокумент`, `Консьюмер: ТестовыйДокумент` | `Документ.кфк_т_ТестовыйДокумент` | `1c.test-documents` |
| `Продюсер: Тестовый РС`, `Консьюмер: Тестовый РС` | `РегистрСведений.кфк_т_ТестовыйРегистрСведений` | `1c.test-information-registers` |
| `Продюсер: Тестовый РС (ПР)` | `РегистрСведений.кфк_т_ТестовыйРегистрСведенийПР` | `1c.test-information-registers-pr` |
| `Продюсер: Тестовый РН` | `РегистрНакопления.кфк_т_ТестовыйРегистрНакопления` | `1c.test-accumulation-registers` |

Дополнительно создаёт `Продюсер: Общий` с настройками всех пяти объектов и блокировками регистрации, сериализации и публикации; `Консьюмер: Общий` — с настройками трёх топиков и блокировками чтения и десериализации. Всего: один брокер, две группы, шесть продюсеров и четыре консьюмера.

Процедура создаёт настройки обмена; сами элементы тестового справочника, документы и записи тестовых регистров она не создаёт. Для обращения к подготовленным объектам модуль предоставляет экспортные методы `СсылкаБрокераПоУмолчанию()`, `СсылкаГруппыПродюсеров()`, `СсылкаГруппыКонсьюмеров()` и методы ссылок отдельных продюсеров/консьюмеров.

### `ИнициализацияПользователей()`

Создаёт администратора средствами БСП, копирует его свойства для `АдминистраторТакси` и создаёт двух пользователей Kafka с ролями из таблицы выше. Для `АдминистраторТакси` устанавливает начальные настройки. Разрешает открытие внешних отчётов и обработок, отключает предупреждения об опасных действиях/безопасности для подготовленных пользователей. Снимает признак `Служебный` у всех имеющих его элементов справочника `Пользователи`, связанных с пользователями ИБ.

## Данные и восстановление состояния

- Разрешено использовать как fixtures данные `ИнициализацияДанных()` и собственные элементы сценария.
- До запуска сценария с записью определите используемые данные, исходное состояние и стратегию очистки/восстановления, включая сбой. Общие подготовленные данные после изменения восстанавливайте; для собственных элементов применяйте предусмотренную сценарием очистку.
- Повторный вызов `ИнициализацияДанных()` обновляет объекты по фиксированным ссылкам и перезаполняет их табличные части во всём описанном наборе. Не используйте его как локальную очистку одного элемента или гарантию полного отката состояния.
